## ١. ملخص الوضع الحالي (Audit)

قرأت محتوى الصفحة الرئيسية كاملًا (`Navbar`, `Hero`, `StatsStrip`, `Features`, `AppFeatures`, `ResearchImpact`, `Zones`, `GoldenRules`, `Screenshots`, `Legacy`, `CommunityChannels`, `Download`, `Footer`) و `layout.tsx`. كما قمت بتدقيق مباشر (live audit) على الموقع المنشور فعليًا على `https://al-tayabat.com/` عبر فحص استجابات HTTP الحقيقية. النتائج:

### ١.٠ نتائج التدقيق المباشر على الموقع المنشور (2026-06-20)

| الفحص | النتيجة | الحالة |
|---|---|---|
| `https://al-tayabat.com/` | `200 OK` — الـ HTML المنشور مطابق تمامًا للكود المحلي (نفس title/description/keywords) | ✅ متطابق، لا مفاجآت |
| `http://` → `https://` | إعادة توجيه `308` صحيحة إلى `https://al-tayabat.com/` | ✅ سليم |
| `https://www.al-tayabat.com` | إعادة توجيه `307` إلى النطاق بدون www | ⚠️ يُفضَّل `308` (دائم) بدل `307` (مؤقت) لنقل قيمة SEO كاملة — هذا إعداد على مستوى Vercel Domains لا الكود |
| `/robots.txt` | **`404 Not Found`** | ❌ غير موجود فعليًا على الموقع المنشور — يؤكد ما ورد في القسم ١.٢ |
| `/sitemap.xml` | **`404 Not Found`** | ❌ غير موجود فعليًا على الموقع المنشور |
| `og:image` / `twitter:image` | غير موجودين في `<head>` المنشور | ❌ مؤكد — لا صورة مشاركة عند لصق الرابط في واتساب/تويتر/فيسبوك |
| `canonical` / `og:url` / `metadataBase` | غير موجودة في الكود المنشور | ❌ مؤكد |
| `/admin` → `/admin/login` | إعادة توجيه `307`، والصفحة تحمل `<meta name="robots" content="noindex, nofollow">` فعليًا | ✅ محمية من الفهرسة بالفعل (لا حاجة لإجراء إضافي عاجل، لكن يُستحسن إضافتها في `robots.txt` أيضًا لتوفير ميزانية الزحف) |
| `Cache-Control` على الصفحة الرئيسية | `private, no-cache, no-store, max-age=0, must-revalidate` | ⚠️ **مشكلة أداء جديدة مكتشفة** — الصفحة الرئيسية تُعرَّف ديناميكيًا بالكامل (لا تخزين مؤقت على الحافة Edge) بسبب استدعاء `getPublicConfig()` من Supabase داخل `Home` (سيرفر كومبونينت غير مزوَّد بـ `revalidate`). هذا يعني أن كل زيارة تنتظر استجابة قاعدة البيانات قبل أي رسم HTML — يؤثر سلبًا على TTFB و Core Web Vitals (LCP)، وهما عاملا ترتيب مباشرين في جوجل |
| `/privacy` `/terms` `/deletion` | `200 OK` لكل الصفحات | ✅ سليمة |

> **النتيجة الإجمالية:** كل ما اقترحته في النسخة الأولى من هذه الخطة بخصوص `sitemap.ts`/`robots.ts`/`metadataBase`/`og:image`/JSON-LD كان تقديرًا صحيحًا 100% — التدقيق المباشر يؤكد أن هذه العناصر **غير موجودة فعليًا** على الموقع المنشور. بالإضافة إلى ذلك، تم اكتشاف **مشكلة أداء جديدة** (Cache-Control الديناميكي) لم تكن واضحة من قراءة الكود فقط.

**موجود حاليًا (جيد):**
- Title و Description في `app/layout.tsx` باللغة العربية ويحتويان على "نظام الطيبات" و "تطبيق الطيبات" و "ضياء العوضي".
- `openGraph` أساسي (title, description, locale, type).
- `lang="ar" dir="rtl"` على مستوى `<html>` — صحيح لـ RTL.
- محتوى غني بالكلمات الدلالية الطبيعية: "تقييم صحي أسبوعي"، "إحصائيات مجتمعية شفافة"، "مستويات الغذاء"، "القواعد الذهبية الست".
- صفحات قانونية موجودة: `/privacy`, `/terms`, `/deletion`.

**مفقود أو ناقص (فرص تحسين فورية):**
1. **لا يوجد `sitemap.xml` ولا `robots.txt`** — لا ملفات `app/sitemap.ts` / `app/robots.ts`.
2. **لا يوجد `metadataBase`** — روابط Open Graph النسبية لن تُحل تلقائيًا لنطاق صحيح.
3. **لا يوجد Open Graph image (`og:image`)** و لا `twitter:card` — `public/` يحتوي فقط على `app_icon.png` (1024×1024 شعار)، لا توجد صورة مشاركة اجتماعية مصممة 1200×630.
4. **لا يوجد structured data (JSON-LD)** — لا `SoftwareApplication`, لا `Organization`, لا `FAQPage`.
5. **لا `canonical` tags**.
6. **كلمة "تطبيق الطيبات" غير موجودة في `keywords`** الحالية (موجود فقط "الطيبات" و"نظام الطيبات").
7. **لا يوجد alt text مخصص بكلمات مفتاحية على الصور** (الشعار alt="شعار الطيبات" فقط — جيد لكنه الوحيد).
8. **لا توجد صفحة/مسار يستهدف "افضل تطبيق لنظام الطيبات"** كعنوان أو H1 مباشر — هذا مصطلح بحث تنافسي (intent مقارنة) ولا يوجد محتوى يستهدفه حرفيًا.
9. **لا يوجد مدونة/محتوى طويل (blog)** يستهدف الكلمات الطويلة (long-tail) مثل "ما هو نظام الطيبات" أو "الأطعمة الممنوعة في نظام الطيبات" — هذا محتوى موجود في `_docs/kb/altayebaat-system-book.md` لكنه غير منشور كصفحات HTML قابلة للفهرسة.
10. **لا alt text على الصور داخل `Screenshots.tsx`** (لم تُفحص بالتفصيل، يُنصح بالتأكد لاحقًا).

### ٢.١ الكلمات الأساسية (Primary — تُستهدف في H1/Title/الصفحة الرئيسية)

| الكلمة | نية البحث (Intent) | أين تُستخدم |
|---|---|---|
| نظام الطيبات | معلوماتي + بحث عن الماركة | H1, Title, الفقرة الافتتاحية |
| تطبيق الطيبات | بحث عن الماركة + تنزيل | Title, H1 ثانوي, CTA |

| تنظيم وجباتك / تنظيم الوجبات | وظيفي (feature-intent) | H2 في Features/AppFeatures |
| تابع تحسنك وتقييمك / تقييم صحي أسبوعي | وظيفي (feature-intent) | H2 في Hero/AppFeatures (موجود فعليًا في الكود) |

### ٢.٢ كلمات ثانوية (Secondary — لأقسام الصفحة الرئيسية الحالية)

- نظام الدكتور ضياء العوضي
- مستويات الغذاء (الأساسي، المحدود، المراقب، الاستثنائي، الممنوعات)
- القواعد الذهبية الست
- نظرية الجسم السيد
- صحة طبيعية / غذاء طبيعي / تغذية علاجية
- مجتمع الطيبات / إحصائيات مجتمعية شفافة
- تطبيق متابعة صحية / تطبيق متابعة غذائية

### ٢.٣ كلمات طويلة (Long-tail — لمحتوى مستقبلي / مدونة)

مصدرها الأساسي `_docs/kb/altayebaat-system-book.md` الذي يحتوي محتوى ثري غير مفهرس حاليًا:

- ما هو نظام الطيبات وكيف يعمل
- الأطعمة الممنوعة في نظام الطيبات

- نظرية الجسم السيد للدكتور ضياء العوضي
- الصيام الأسبوعي (الاثنين والخميس) وفوائده
- الفرق بين نظام الطيبات والكيتو/الصيام المتقطع
- تطبيق عربي لتتبع الوجبات الصحية

>
> ⚠️ **تنبيه على الكلمات الطويلة المتعلقة بالأطعمة** ("الأطعمة الممنوعة..."، "الأطعمة المسموحة..."، "جدول وجبات...") أعلاه: استهدافها كـ**كلمات بحث** في العناوين/الوصف مقبول (الناس يبحثون بهذه العبارات فعليًا)، لكن المحتوى الذي يستقبل هذا الزائر **لا يجب أن يسرد الأطعمة أو الوجبات بالاسم** — راجع القواعد الإلزامية في القسم ٧.٠ قبل كتابة أي صفحة تستهدف هذه الكلمات.

## ٥. الملفات التقنية المفقودة

### ٥.١ `app/sitemap.ts` (جديد)

```ts
import type { MetadataRoute } from "next";

export default function sitemap(): MetadataRoute.Sitemap {
  const base = "https://al-tayabat.com";
  const routes = ["", "/privacy", "/terms", "/deletion"];
  return routes.map((route) => ({
    url: `${base}${route}`,
    lastModified: new Date(),
    changeFrequency: route === "" ? "weekly" : "yearly",
    priority: route === "" ? 1 : 0.3,
  }));
}
```

### ٥.٢ `app/robots.ts` (جديد)

```ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      { userAgent: "*", allow: "/", disallow: ["/admin"] },
    ],
    sitemap: "https://al-tayabat.com/sitemap.xml",
  };
}
```

> مسار `/admin` موجود في `tayabat_web/app/admin` وهو لوحة تحكم داخلية. التدقيق المباشر (القسم ١.٠) أكّد أن `/admin/login` يحمل فعليًا `<meta name="robots" content="noindex, nofollow">` — أي أنه **محمي من الفهرسة بالفعل على مستوى الصفحة**. إضافته إلى `robots.txt` كما هو موضح أعلاه ليست لإصلاح ثغرة، بل لتوفير ميزانية الزحف (crawl budget) بمنع الزواحف من زيارته من الأساس.

## ٧. فرص محتوى جديد (Content Roadmap)

المحتوى الموجود في `_docs/kb/altayebaat-system-book.md` غني جدًا (سيرة الدكتور، 25 نظرية علمية، أبواب الأطعمة المسموحة/الممنوعة، القواعد الذهبية) لكنه **غير منشور كصفحات HTML قابلة للفهرسة** — هذا أكبر فرصة SEO غير مستغلة في المشروع. لكن نشره يجب أن يخضع لقواعد واضحة (القسم ٧.٠ أدناه) قبل أي تنفيذ.

### ٧.٠ قواعد إلزامية لأي محتوى يُستخرج من الكتاب

> هذه القواعد تُلغي وتحلّ محل أي افتراض ضمني في النسخ السابقة من هذه الخطة بأن صفحات المحتوى ستكون "استخراجًا" مباشرًا من الكتاب.

1. **إعادة الصياغة الكاملة، لا النسخ:** ممنوع نقل أي جملة من `altayebaat-system-book.md` كما هي. كل صفحة منشورة يجب أن تكون بصياغة أصلية جديدة تنقل الفكرة لا النص الحرفي.
   - **لماذا (SEO):** نشر نص مطابق لنص منشور أصلًا (الكتاب نفسه متاح للمشاركة العامة بنص ثابت بحكم ترخيصه) يخلق خطر **محتوى مكرر (duplicate content)** يُضعف ترتيب الصفحة الجديدة بدلًا من تقويته.
2. **محتوى مفاهيمي/فلسفي فقط — بلا أمثلة وجبات أو قوائم أطعمة محددة بالاسم:** الصفحات المنشورة تشرح *المبدأ* (مثل "النظام يصنّف الأطعمة إلى مستويات بحسب درجة تكرارها") ولا تذكر أصنافًا أو وجبات بعينها (مثل تسمية صنف غذائي محدد بالاسم، أو جدول وجبات تفصيلي).
   - **لماذا:** تفاصيل الوجبات والأصناف وتصنيفاتها هي بيانات تشغيلية تُدار وتُحدَّث داخل التطبيق (قاعدة بيانات الوجبات في Supabase/`meals.json`) وقد **تتغير لاحقًا**. أي قائمة أطعمة تُنشر كنص ثابت على صفحة ويب ستُصبح بمرور الوقت غير دقيقة أو متعارضة مع ما يعرضه التطبيق فعليًا — وهذا يُسيء لمصداقية الموقع في نتائج البحث (مستخدم يقرأ في جوجل قائمة قديمة بينما التطبيق يعرض قائمة مختلفة).
3. **دعوة دائمة لاستخدام التطبيق للتفاصيل:** كل صفحة تنتهي بفقرة/CTA صريحة توجّه القارئ إلى التطبيق للحصول على التفاصيل الفعلية والمحدثة، بصياغة من نوع: *"لمعرفة التصنيف الكامل والمحدث لكل صنف غذائي، والوجبات المقترحة لمستواك الصحي، حمّل تطبيق الطيبات"* — هذا يحوّل صفحة معلوماتية إلى قناة تحويل (conversion) فعلية لتنزيل التطبيق، وفي نفس الوقت يُبقي الموقع "صحيحًا دائمًا" SEO-wise لأنه لا يَعِد بتفاصيل قد تتغير.
4. **ما يصحّ نشره بأمان (لأنه مبادئ ثابتة لا بيانات تشغيلية):** فلسفة النظام، نظرية الجسم السيد، القواعد الذهبية الست (كمبادئ سلوكية، لا كجرعات/كميات محددة قابلة للتغيير)، سيرة الدكتور ضياء العوضي، الشرح العام لوجود "مستويات غذاء متدرجة" (بالاسم والمفهوم كما في `Zones.tsx` الحالي على الصفحة الرئيسية — الذي بالفعل لا يسمي أصنافًا بعينها، وهو نموذج جيد يُحتذى).
5. **ما يجب تجنّبه تمامًا في صفحات الويب الثابتة:** تعداد أسماء أطعمة مسموحة/ممنوعة، جداول وجبات أسبوعية، كميات أو تكرارات محددة بالأرقام لصنف معيّن — كل هذا ينتقل حصرًا إلى داخل التطبيق.
